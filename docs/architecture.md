# ContextForge Panel 架构

ContextForge Panel 是独立部署的管理与使用控制台，以 ContextForge v1.0.11 为后端基线。管理员和普通用户共用应用，实际资源可见性与操作授权由后端决定。参考仓库只读，不复用原前端。

## 部署边界

单容器内 Node.js 同时服务 React 静态文件和固定上游代理。`APP_ROOT_PATH` 是外部公共前缀；页面占用 `/app/`，控制台内部接口占用 `/_panel/`，其他业务路径原样转发到 `BACKEND_URL`。后端内部前缀与公共前缀独立。页面导航使用 hash，邮件重置和邀请链接另支持干净路径；运行时注入资源基址，不依赖构建时部署地址。

代理保持流式响应、会话头、取消与 WebSocket；不接受客户端指定上游。登录令牌仅保存在控制台服务端，浏览器的 HttpOnly Cookie 保存随机会话标识。浏览器写操作验证 Origin，外部客户端使用自己的 Authorization，不继承浏览器会话。需要浏览器跳转的 OAuth 授权使用绑定会话、限时且一次性的固定上游导航票据。

## 权限与凭据

前端查询当前用户、角色、权限、团队，不推断用户拥有的权限。Key 申请指用户在已有权限范围内自助创建，不增加审批授权系统。明文 Key 仅在创建响应中显示，不放入 URL 或持久化浏览器存储。后端仍执行令牌范围与 RBAC 两层检查。

## 接口覆盖

准确标签的后端路由源码与运行时 OpenAPI 共同构成契约。常用业务采用专门的目录、表单、批量操作和权限页面；完整业务接口目录提供按 Schema 填写参数、请求体和执行结果的操作入口。内部、健康、废弃接口分类排除，协议接口通过连接示例和调试覆盖。源码提取结果不冒充运行时规范或集成测试证据。

## 批量操作

优先原生批量 API，否则并发受限逐项执行，记录每项结果。跨分页选择先枚举并冻结目标集合；失败重试不重复成功项。多个 HTTP 请求不具备事务回滚。

## 验证

代理测试覆盖路径、Cookie、身份隔离、Origin、流式响应与 WebSocket。浏览器测试覆盖登录、普通用户 Key 创建与撤销、资源与 RBAC。真实后端验证单独记录版本、配置和结果；LLM Chat 兼容旧版需单独验证，不能以模拟数据替代。
