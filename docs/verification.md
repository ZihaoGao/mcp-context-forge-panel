## 接口契约与功能关闭

完整业务方法映射见 `contracts/contextforge/coverage.csv`。规范来自真实后端捕获，以及未启动外部服务的条件 router 规范生成。清单中的业务方法都具有接口工作台操作入口；常用资源还具有专用列表、表单、批量操作或权限页面。

这不意味着每个业务方法都已经连接真实业务服务测试。Vault、SIEM、ToolOps、企业 SSO、真实 LLM 供应商、外部 MCP/A2A/gRPC 服务的连接配置仍需在目标部署验收。原前端 HTML 渲染接口、内部服务 API、健康探测和已废弃操作有明确排除理由。

## 已知边界

- v1.0.11 的 MCP 2.x 与当前 Chat 适配器依赖不兼容；Chat 使用 v1.0.10 验证。
- 测试中后端登出后的旧 JWT 可能仍被认证缓存接受。控制台先销毁自己的服务端会话，同时调用后端撤销，确保旧控制台 Cookie 无法重放；不声称修复后端自身的所有认证入口。
- 会话存于单个控制台进程，重启需重新登录；多副本部署需要后续引入共享会话存储。
- 跨多个请求的批量操作可能部分成功，结果逐项展示，重试只针对失败项。
- 低频业务能力采用 Schema 驱动的操作表单；复杂嵌套配置保留 JSON 编辑，不复用原前端。
