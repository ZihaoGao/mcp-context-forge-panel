## 已知边界

- v1.0.11 的 MCP 2.x 与当前 Chat 适配器依赖不兼容；Chat 使用 v1.0.10 验证。
- 测试中后端登出后的旧 JWT 可能仍被认证缓存接受。控制台先销毁自己的服务端会话，同时调用后端撤销，确保旧控制台 Cookie 无法重放；不声称修复后端自身的所有认证入口。
- 会话存于单个控制台进程，重启需重新登录；多副本部署需要后续引入共享会话存储。
- 跨多个请求的批量操作可能部分成功，结果逐项展示，重试只针对失败项。
- 低频业务能力采用 Schema 驱动的操作表单；复杂嵌套配置保留 JSON 编辑，不复用原前端。
- 当前资源导入导出的真实浏览器往返验证覆盖虚拟服务器与本地 REST 工具定义；不声称每种资源、每种认证方式、每个行内操作及每个原生迁移冲突策略都经过真实业务端到端测试。MCP 接入新增交互使用固定响应验收，真实外部上游连接与调用仍需在目标部署验证。插件 / 目录依照契约适配，仍需在启用这些资源的目标部署验收。
